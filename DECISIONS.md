# Decisions

Every scope or technical decision, with a one-line rationale. This file is the raw material for
`docs/IMPROVEMENT_CHANGELOG.md` — write entries as decisions are made, not afterwards.

| Date | Decision | Rationale |
|---|---|---|
| 2026-08-29 | Replay is the graded path; live is demo-only | Live streams are not reproducible; judges cannot re-run a broadcast |
| 2026-08-29 | Content-addressed model-call cache, committed | Lets judges reproduce every number with no API keys and zero cost |
| 2026-08-29 | Two primary metrics instead of a composite GS-F1 | A 4-clause matching rule is unstable on 12 cases and illegible in a 5-minute video |
| 2026-08-29 | Unsupported-card rate as a primary metric | Deterministically checkable with no gold labels, so it scales to every fixture |
| 2026-08-29 | Baseline receives the same raw multimodal events | Comparing against chat-only would measure extra data, not the agentic workflow |
| 2026-08-29 | One agent, bounded tools; no web-search or scheduler agent | Neither addresses a demonstrated failure; PDF states purposeful choices beat component count |
| 2026-08-29 | Dashboard is the landing page | Halves the frontend work and feeds End-to-End Quality instead of competing with it |
| 2026-08-29 | API-only, `deepseek-v4-flash` | No local compute available; `deepseek-chat` retired 2026-07-24 |
| 2026-08-29 | Cache key names media by SHA-256; bytes never enter the entry | The cache is committed for keyless reproduction — a 19 MB WAV or 100 KB of base64 per frame does not belong in git |
| 2026-08-29 | Deepgram via REST + `httpx`, no SDK | `httpx` is already a dependency; an SDK would add a version surface for one POST |
| 2026-08-29 | Frame prompt written fresh, not ported from `legacy/.../image_annotations/workers.py` | The loop's context guardrail allows only three legacy files; the intent (factual, ≤500 chars, "text unclear" over invention) was already recorded in the enrich docstring |
| 2026-08-29 | Enrichment writes rows without `id`; the replay loader derives them | One implementation of the id rule, so the writer and reader cannot drift; `EventIndex` already rejects duplicates |
| 2026-08-29 | Deepgram `utterances` preferred, word-grouping only as fallback | Deepgram's own final segmentation beats a hand-tuned pause threshold, and the fallback keeps enrichment working if the flag is ever dropped |
| 2026-08-29 | Analysis windows are fixed 60 s tiles derived from the fixture span | Window bounds enter the prompt; tiling on event volume or wall-clock would change every cache key and break replay reproduction |
| 2026-08-29 | Agent and baseline run through one `_run_over_fixture` on identical windows | The eval compares them — any difference other than the system itself would be measured as an improvement it did not earn |
| 2026-08-29 | The CLI reports counts, never rates | `evals/scorer.py` owns every published metric; a second implementation would eventually disagree with it in print |
| 2026-08-29 | `trace_id` derived from `(agent, case_id)`, not `uuid4` | Unseeded randomness leaked into the published result document, so two replays of one fixture differed and each run orphaned a trajectory file |
| 2026-08-29 | `serve` uses stdlib `http.server`, not the declared FastAPI/uvicorn | `make demo` is off the graded path; stdlib keeps the fresh-clone install smaller and has no startup surface |
| 2026-08-29 | `serve` never runs the agent — it only serves what `make replay` wrote | What a judge sees on screen is then exactly the file they can open and diff |
| 2026-08-30 | The eval scores every card a system emits, verified and rejected alike | Scoring only gate survivors makes the unsupported-card rate zero for both systems by construction — the headline metric would measure nothing |
| 2026-08-30 | `latency_ms` and `cost_usd` stay `None` in `comparison.csv` | A replay run reads cached responses, so timing it measures disk, not the model; publishing that as latency would be a fabricated number. Cost lives in `COST_LEDGER.md` |
| 2026-08-30 | Chat-only ablation is opt-in (`--ablation`), not part of the default eval | It is a diagnostic, not the headline comparison, and every extra system is 12 more paid calls in the record phase |
| 2026-08-30 | `evidence/predictions.json` written on every run | Frozen protocol item 4 — raw predictions, gate decisions and trace id per case, failures included, not only the wins |
| 2026-08-30 | Only 4 eval cases built; the other 8 wait for real captures | The scaffold fixture contains three phenomena in 24 s. Authoring a fixture to contain sarcasm or a diarization failure and then grading on it would be grading the system against a script it was handed |
| 2026-08-30 | Every case declares `fixture_kind`; only `capture` is reportable | Without it a pipeline smoke-run on synthetic data silently becomes a published number — the exact integrity failure the legacy frontend committed |
| 2026-08-30 | `report.md` banners non-capture fixtures and lists every fixture's provenance | A judge opens `evidence/report.md` first; the table has to say what it is measuring before it shows a number |
| 2026-08-30 | Case 12's abstention window has a frame caption but zero chat | An empty window is a trivial test; stream context with a silent audience tests the real failure — inventing a signal out of context alone |
| 2026-08-30 | The debrief takes only gate-verified cards | It is what a streamer reads after the broadcast; a card whose evidence did not check out has no business in it. The eval scores rejected cards too, but that is measurement, not the product |
| 2026-08-30 | Recurring themes count words from trigger quotes and answer distributions, never card titles | Titles are prose the model wrote — the first version of the section returned "chat", "says" and "the", i.e. it measured the summariser's phrasing rather than the session |
| 2026-08-30 | Themes use a twelve-word visible stopword list, not a package or a model call | Extendable from observed noise, auditable at a glance, and it cannot change a cache key |
| 2026-08-30 | Clip candidates exclude cards whose trigger is `unknown` | Density alone is not a clip: with no established cause there is no moment to cut to |
| 2026-08-30 | Timecodes resolve through the triggering event, falling back to the window start and saying so | A debrief that prints a confident timestamp derived from a 60 s bucket is quietly wrong; the label makes the precision visible |
| 2026-08-30 | Dashboard is written fresh, nothing ported from `legacy/frontend/` | The port would have carried the generators, the Spline blob and the purple gradients — the exact things DESIGN.md says to delete — and the loop forbids reading that tree at all |
| 2026-08-30 | No CDN, no webfont fetch, no build step; vanilla JS in three static files | A judge with no connectivity must still see the real dashboard, and a build step is another way a fresh clone fails to run |
| 2026-08-30 | Status vocabulary is verified / abstained / rejected, not DESIGN.md's "uncertain" | A card whose evidence did not check out is not uncertain; calling it that would soften the one failure mode this product exists to surface |
| 2026-08-30 | Rejected cards are rendered on the page, in their own labelled block | A system that hides its own rejects cannot be audited, and the gate working is the strongest thing the demo has to show |
| 2026-08-30 | `/api/replay` sends only the events the cards cite, not the fixture | The drawer needs message text; shipping a whole fixture to the browser is wasteful and would let the page display chat no card stood behind |
| 2026-08-30 | Colour conformance is a test, not a convention | The rule "do not improvise colours" is the one the previous shell broke; every hex in `app.css` must appear in `DESIGN.md` or the build fails |
| 2026-08-30 | `pyproject.toml` with a src layout; `make setup` installs the package editable | Every documented command failed from a clean clone with `ModuleNotFoundError`, and reproducibility is a gate before scoring — a project that cannot start is never read |
| 2026-08-30 | Runtime dependencies stay in `requirements.txt`, not in `pyproject.toml` | They are pinned and split into replay / live-capture / dev groups; declaring them twice is how the two lists drift apart |
| 2026-08-30 | The README leads with what is NOT measured yet | A reader who finds the caveat after the results table has already been misled once; the exit-3 behaviour is a strength and reads as one when stated first |
| 2026-08-30 | Twitch retention and Jan-2026 cost figures kept out of the README | They come from planning notes rather than a source. Recorded as UNVERIFIED in `RISKS.md`; the README makes the same points qualitatively |
| 2026-08-30 | The documented test count is asserted by a test | It is the first number a reviewer checks, and it silently drifted by nine within one iteration of being written down |
| 2026-08-30 | Documented `make` targets are checked against the Makefile by a test | A reproduction guide naming a target that does not exist fails the reviewer at the step that decides whether the project is scored at all |
| 2026-08-30 | Secret scan moved from a Makefile grep to `scripts/scan_secrets.py` | The grep never reached `.env` on macOS, matched its own pattern list so the check was always red, and skipped `legacy/` while `legacy/` stayed in the tree — three ways to be reassured by nothing |
| 2026-08-30 | The scan prints `path:line` and a rule name, never the matched text | A gate that echoes credentials into a terminal, a CI log or a transcript has moved the leak rather than found it |
| 2026-08-30 | Two severities: leak in a project file vs. local-only file present | `.env` existing is correct on a working machine and fatal in an archive; collapsing the two makes the operator ignore both |
| 2026-08-30 | DB user, host and name count as credentials alongside the password | They are one connection block. The first pass fired only on the password line and left the rest of `legacy/README.original.md` unreported |
| 2026-08-30 | `legacy/README.original.md` left unmodified despite holding live credentials | `docs/PRE_EXISTING.md` states `legacy/` is preserved as-is; rotating and excluding it from the archive is the author's call, and silently editing a disclosure artifact is worse than flagging it |
| 2026-08-30 | `TS_TRACE_DIR` redirects trajectory output, set session-wide in conftest | The suite wrote 55 files into a graded deliverable; redirecting once fixes the class of problem instead of the instances, and mirrors how `TS_LLM_MODE` already works |
| 2026-08-30 | The 55 test-artifact traces were deleted rather than left in place | They are regenerable output with case ids no evaluation case has; leaving them means the deliverable directory misrepresents what was run |
| 2026-08-30 | `trajectories/README.md` lists all three systems as `[TBD]` rather than only what exists | Three systems are compared, so three trajectories are owed; a README that lists only the ones that exist reads as complete when it is not |
| 2026-08-30 | The coding-agent disclosure lists what the sessions found, not only what they built | A disclosure that claims productivity and omits the defects the agent introduced or missed is not a disclosure |
| 2026-08-30 | No chat transcript is claimed; `PROGRESS.md` and `DECISIONS.md` are named as the record | They were written as the work happened. Producing a transcript after the fact would be exactly the reconstruction the trajectory rules forbid |
| 2026-08-30 | `.env` is deliberately not auto-loaded; keys are exported instead | `.env` here also sets `TS_LLM_MODE`, so `load_dotenv()` would let a local file silently flip a reviewer's replay run into live or record mode — the reproducibility guarantee would depend on a file nobody sees |
| 2026-08-30 | `RISKS.md` reordered by severity with a critical-path header, numbers kept stable | It had become a log. A reviewer needs to know what to do first and what everything else is waiting on; `PROGRESS.md` refers to the numbers, so rows move but never renumber |
| 2026-08-30 | Superseded risks are kept and marked rather than deleted | #9 split into #14 and #15; deleting the row would erase why the policy exists |
| 2026-08-30 | Six unused dependencies removed, plus `pytest-asyncio` | An AST census found no import of any; each was install time and supply surface on the path a judge walks before the project is scored. `mypy` stayed — it is run as a command, not imported |
| 2026-08-30 | The reduction was proved in a clean venv, not asserted from the working one | The packages were still installed locally, so a green suite here would have proved nothing about their necessity |
| 2026-08-30 | A test fails the build when a declared package is never imported | Dead dependencies come back one convenience import at a time; the census that found these six should not have to be run by hand again |
| 2026-08-30 | The keyless guarantee is asserted by executing the chain with sockets rigged to raise | Reading the code and concluding it looks offline is how the secret scan was trusted for a week; the property is cheap to actually run |
| 2026-08-30 | The fake provider is installed only around the record step, never during replay | If the fake stayed in place, a replay that tried to call out would be caught by the fake instead of by the socket trap, and the test would prove nothing |
| 2026-08-30 | C2 split into the part that needs fixtures and the part that does not | The keyless property is checkable today on the scaffold; waiting for #2 to check any of it would have left the gate criterion unverified all night |
| 2026-08-30 | `capture_media` refuses to run into a directory that already holds frames | A re-run stamped already-timestamped frames from zero against a new start time, silently corrupting every frame timestamp — and capture is precisely the step that gets retried after it fails |
| 2026-08-30 | A capture producing no frames or no audio raises instead of returning | It returned success and wrote a `meta.json` declaring a good fixture; the emptiness would have surfaced at enrichment, hours later, with the broadcast over |
| 2026-08-30 | ffmpeg's return code is checked and its stderr surfaced | Nothing inspected it, so a missing binary or a bad argument produced an empty capture that looked like a quiet stream |
| 2026-08-30 | `stamp_frames` extracted from `capture_media` and tested directly | The timestamp arithmetic is the contract `enrich` depends on, and it was reachable only through streamlink and ffmpeg |
| 2026-08-30 | A test drives capture → enrich → `load_fixture` across the real seam | That join decides whether a recorded fixture is usable at all, and it would otherwise be discovered at 5am |
| 2026-08-30 | The architecture diagram marks every node with the file that implements it | A diagram showing a design rather than a build is worth nothing to a reviewer who opens `src/` — and it is how a summary hierarchy nobody wrote ended up claimed in two documents |
| 2026-08-30 | The unbuilt summary hierarchy is listed and marked, not quietly dropped | Dropping it makes the design look smaller than it is; listing it unmarked claims work that does not exist. Naming it as a gap does neither |
| 2026-08-30 | The architecture diagram now includes capture, enrich, the cache and the eval harness | The previous one omitted exactly the parts carrying Reproducibility and Measured Improvement — 30 of the 100 points |
| 2026-08-30 | Documented `make` targets are matched only inside code spans | The prose "make the design look smaller" was read as a target named `the`; a guard that fires on English gets disabled rather than fixed |
| 2026-08-30 | The approve action is a real button producing a real draft, not a status label | It is the last link of the product invariant. A card reading "pending approval" with nothing to press is a chain that ends in a caption |
| 2026-08-30 | The draft is built server-side in `report/poll.py`, not assembled in the browser | What a streamer approves has to be derived deterministically from verified evidence, and that belongs somewhere testable |
| 2026-08-30 | `poll.py` contains no client, token or request, and a test enforces that | Ground rule 06 keeps polls as drafts; the cheapest way to keep it true is for the code path to hold nothing capable of sending |
| 2026-08-30 | Poll shares count every vote, not only the options that survived the cap | Renormalising would print a percentage disagreeing with the card directly above it on the page |
| 2026-08-30 | A card with fewer than two counted options does not become a poll | A poll with one choice is not a poll, and inventing a second option would be fabricating audience input |
| 2026-08-30 | A draft from an abstained card uses the card title and says so | Without an established cause there is no quote to ask; presenting the title as the streamer's own words would be the invention the gate exists to prevent |
| 2026-08-30 | A `none` card is checked for self-contradiction, not for evidence | It asserts nothing, so there is nothing to verify; requiring citations from a card that claims nothing made correct abstention score worst on the headline metric |
| 2026-08-30 | An abstention citing messages or naming a cause is a violation | Those are the only ways it can be wrong: it would be claiming something while declaring that nothing happened |
| 2026-08-30 | Passing abstentions are not free — the other metrics still catch over-abstention | Signal recall and abstention correctness both punish abstaining where a signal existed, so the gate does not need to double as that check |
| 2026-08-30 | A passing `none` card is labelled `abstained`, not `verified` | It is not a verified signal, and the dashboard and debrief already use that word |
| 2026-08-30 | The gate's window is half-open `[start, end)`, matching `events.window` | Two conventions in one system means the gate verifies evidence the agent's own tools never returned; adjacent tiles make that a boundary case on every window, not an edge case |
| 2026-08-30 | A test asserts every frozen gold card passes the gate | Gold labels describe what a perfect system emits. If a tightening invalidates the frozen set, that has to surface on the same commit, not in the results table |
| 2026-08-30 | Evidence must be a `chat_message`; any other event type is a violation | The gate accepted any id, so a card could cite the transcript segment that caused the signal as the audience's response to it — self-supporting and verified |
| 2026-08-30 | The trigger appearing in its own evidence list is a violation in its own right | The type check already prevents the common case, but stating the circularity rule explicitly is two lines and says what the gate means |
| 2026-08-30 | The short-quote hole is documented, not fixed | The frozen metric definition says "does not appear verbatim"; tightening it after publication would make the reported numbers incomparable to the metric they claim to be. Recorded in README §11 and RISKS #28 |
| 2026-08-30 | Punctuation is stripped by Unicode category, keeping symbols | `[^\w\s]+` deleted emoji along with punctuation, so an emote flood — the reaction the product most needs to catch — reduced to nothing and disappeared |
| 2026-08-30 | A punctuation-only message goes to a counted `∅` bucket rather than being dropped | Burst counts have to sum to the messages in the window; anything dropped is volume the agent never sees and a distribution that quietly under-counts |
| 2026-08-30 | The emote fix was checked against the frozen fixture before being kept | It reduces identically — 32 → 15 bursts, ratio 0.469 — so no cached prompt or frozen case moves. A correctness fix that shifts frozen numbers is a different decision and would need saying out loud |
| 2026-08-30 | Trigger accuracy keeps a matched-card denominator, and `unmatched_rate` is reported beside it | Gold is not exhaustive on twelve cases, so scoring every emitted card would penalise a real signal nobody labelled. The honest fix is to publish what is computed and expose the hole next to it, not to redefine the metric to sound better |
| 2026-08-30 | Gold matching is one-to-one, assigned in emission order | A gold signal can be found once. Without it a duplicate card weighted one signal twice, and emission order keeps the assignment reproducible |
| 2026-08-30 | The README now describes the metric the code computes, with the probe that exposed the gap | A published definition the implementation does not honour is worse than a narrower metric honestly described |
| 2026-08-30 | The card cap is enforced by the controller, in one function shared by both systems | A cap that lives only in the prompt is a hope, and the eval promises both systems the same one — measured, ten cards in gave ten cards out, for both |
| 2026-08-30 | Unknown card types are filtered before the cap is applied | Otherwise five junk cards fill the cap and squeeze out the real ones |
| 2026-08-30 | Dropped cards and dropped tool calls are both reported, never silent | A silently truncated tool-call list is indistinguishable to the model from a tool that returned nothing, and a silently dropped card is a claim the system made and hid |
| 2026-08-30 | Eval set rebuilt on real captures; the four synthetic cases deleted | A case on the scaffold fixture is bannered NOT A REPORTED RESULT, so it can never contribute a graded number |
| 2026-08-30 | 11 cases, not 12 | The cut case's window sat 72% inside c05's on a 120 s fixture; two cases sharing most of their events are not two independent measurements |
| 2026-08-30 | No numeric-rating or binary-choice case | Zero bare-number replies exist in any fixture and the one real binary question lands 8 s before its fixture ends. Authoring a fixture to contain the phenomenon would be grading against a script |
| 2026-08-30 | Gold evidence ids resolved from the fixture by script, never typed | A mistyped id is not an error, it is a silent miss that scores a correct card as wrong and quietly deflates every metric |
| 2026-08-30 | Gold signals are pushed through the real provenance gate in a test | Gold that cannot itself pass the gate makes the whole eval unmeasurable; the failure is invisible at run time |
| 2026-08-30 | Gold marked `reviewed: false` and surfaced in README §6 | The labels are model-drafted. Claiming human ground truth that does not exist is the one unrecoverable mistake in an evaluation |
| 2026-08-30 | Runner tests own their case data via a `stub_cases` fixture | Ten tests about the eval harness broke when the graded case set changed; the harness must be testable independently of the deliverable it scores |
| 2026-08-30 | Git history disclosed as reconstructed in README and PRE_EXISTING | The tree was never under version control, so commit dates are assigned. Letting a judge read `git log` as observed history would be a fabricated timeline |
