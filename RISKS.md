# Risks

Anything that could fail in the open — security, privacy, correctness, reproduction. Numbers are
stable across revisions because other documents cite them, so rows are reordered by severity and
**never renumbered**. A test fails if any number is used twice.

Two rows added on 2026-08-30 reused numbers that were already taken (36 and 37). The **originals
keep their numbers**; the later additions became **44** and **45**.

## The live list

Reviewed against the tree 2026-09-02. The submission-gate rows this file opened with are gone:
the repository is public and level with local, and a promotional video is not a product concern.
What is left is real.

**Security and privacy, still open.** `.env` (#17) and the team Telegram history (#1) hold live
credentials that need rotating — that was true a week ago and is still true. **#53 is
the one to read**: pseudonymisation covers the author field, not `@mentions` inside message text,
and the four evaluated fixtures carry 172 mentions naming 88 distinct real handles. It is
documented rather than fixed, because event ids are content-derived and rewriting text would
break every cache key and with it keyless reproduction.

**Accuracy.** The **gold labels** (#36) are model-drafted and unconfirmed; `evals/REVIEW_ME.md`
is a ten-minute pass written for exactly that. The measured result is mixed and is reported that
way: the agent doubles the baseline's recall and loses the headline unsupported-card rate. That
is #38, a finding rather than a defect — and part of it (#38's circular-evidence rejections) was
a rule this build imposed that the original product never had.
