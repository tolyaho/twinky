    02 — how it works

    Four steps, no magic

    Every number on this page comes out of the same four steps, replayed from a committed cache with no API keys.

    1. 01Capture Chat, audio and frames off a live broadcast. No keys, no model.
    2. 02Ground Speech and screen become events beside the chat, on one timeline.
    3. 03Verify A deterministic gate checks every citation. Unprovable cards are rejected.
    4. 04Report What survived, what did not, and the evidence for both.
    03 — is it actually better

    Measured improvement

    Eleven frozen cases across four real broadcasts, scored on every card each system emits — verified and rejected alike. Reproduced by make eval from the committed response cache with no API keys.

    systemcardstrigger accuracy unmatchedunsupportedrecall

    The agent wins grounding and loses restraint: it doubles the baseline’s recall and is the only system that names a correct cause, and its unsupported-card rate is the worst of the three. Both halves are reported and neither prompt was edited after the numbers were seen. The chat-only ablation’s trigger accuracy rests on a single matched card, which is why unmatched is printed beside it.

    04 — untrusted input

    Needs a look, and nothing more than a look

    Chat is untrusted data. Three deterministic rules read it and produce suggestions — no model, no cost, and no button that does anything. A rule that found nothing says so, because otherwise you cannot tell "we checked and it is clean" from "we never checked".

    05 — how it got here

    What changed, and what it cost

    Every repair with its measured before and after — including a first run that was discarded rather than published — is in docs/IMPROVEMENT_CHANGELOG.md.

    1. largest contributor The baseline had been handed the agent’s tool-calling prompt, so it replied with a tool call, the parser turned that into an empty list, and it scored zero cards across eleven cases. Fixing it is what made a comparison exist at all.
    2. removed experiment Amplifying the sleep-stream audio by 28 dB produced zero additional transcript segments. Reverted — it turned a suspected pipeline bug into a verified property of the fixture: nobody is speaking.
    3. main failure mode On the word-puzzle case the agent returned “no clear speech or on-screen content detected” without ever calling get_frame_captions — declaring the screen empty without looking at it. Not fixed here: changing a prompt after seeing the score invalidates the comparison.
