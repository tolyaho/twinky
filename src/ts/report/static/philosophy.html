Live Method Why
the argument

A chat message is not text. It is a response to something.

10 means nothing. 10 thirty seconds after “how would you rate this?” is a rating. Every attempt to read chat as text is reading the answer without the question — and the question is in the audio and on the screen, never in the chat.

01 — the claim

Grounding is retrieval and proof, not summarization

A language model will happily summarise a thousand chat messages. It will also happily tell you what caused them, and it has no way to know. The difficulty is not producing a fluent account of a stream — that is easy, and it is why every chat tool produces one. The difficulty is showing which stream event caused which audience reaction, and being willing to say when you cannot.

So the unit here is not a summary. It is a card that names a cause, quotes it verbatim, and cites the messages it is standing on — and a deterministic gate that throws the card away when any of that fails to check out. The gate is not a safety net bolted on afterwards. It is the product.

02 — the uncomfortable part

The system that knew least won the headline metric

The evaluation compares three systems on eleven frozen cases. The chat-only ablation — the one deliberately starved of speech and screen — came first on unsupported-card rate, 0.280 against the full agent's 0.739.

It won by abstaining. With no transcript and no captions it had no candidate causes to name, so it returned unknown eighteen times out of twenty-five, and an abstention is always gate-clean. Give a system more context and it starts making claims; claims can be wrong, and this metric measures wrongness.

Two things follow, and neither is convenient. An unsupported-card rate cannot be read alone — it is minimised by saying nothing, so it belongs beside recall, where the ablation's single matched card tells the rest of the story. And the shape of the problem is exactly this trade: the agent is the only system here that ever named a correct cause, and it paid for that by being wrong more often. Moving recall without buying it in unsupported claims is the whole game. This run says we have not won it.

03 — the discipline

Nothing was tuned after the numbers were seen

Every change made after the first measurement is labelled repair in DECISIONS.md, with its reason. There are no tuning entries. Two obvious score-raising changes were identified, written down, and refused — including one that follows from a principle this project had already adopted elsewhere, because applying it here would have moved a published number in our favour after publication.

The first measured run was discarded rather than reported: the baseline had been handed the agent's tool-calling prompt and scored zero cards across all eleven cases. make eval now prints BROKEN — NOT A RESULT and exits non-zero if any system emits nothing, because that failure looks exactly like a result.

04 — what is still wrong

Stated here rather than buried

  1. main failure The agent names a chat message as the cause of the chat it is explaining — fourteen of twenty-three cards — and grounds nothing on any recorded fixture. The fix is a tool-selection change, and it was not made, because choosing it after seeing the score is the definition of tuning.
  2. unconfirmed Gold labels were drafted with model assistance. All eleven still read "reviewed": false. Claiming a human review that did not happen would be the one unrecoverable mistake in an evaluation.
  3. not built The 1m/5m/30m/2h summary hierarchy is part of the product thesis and does not exist. It is marked as a gap in the README and the architecture diagram rather than quietly omitted.
  4. reconstructed This repository's git history was rebuilt from a tree that was never under version control. The order is real; the dates are assigned from the session log.
05 — the hot take

Livestreaming is the only medium whose artifact is built to evaporate

The honest objection is that top streamers do not read chat and do not want a tool that reads it for them. That is right, and it is not what this is. The pitch is recover what you are structurally unable to see, and what the platform is about to delete. A streamer who ignores chat live still wants the unanswered-question list and the clip candidates afterwards.

Twitch deletes the VOD, and the chat replay with it, within weeks. Everything the audience said is gone. The second half of this product is memory — and memory is only worth having if each thing in it can show why it is there.

Every number on this site is reproduced by make eval from a committed cache, with no API keys and zero cost. The ones that count against the product are on the method page, unchanged.
